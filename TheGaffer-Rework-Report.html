01 — The Brief

Executive summary

TheGaffer is sound in shape but carries the three classic hazards of a long-lived Bukkit plugin. The core engine has barely changed since 2019 — four years of commits added features, not fixes — so the findings below are current, not historical. Two items dominate the rework: job persistence is currently disabled, and a sister plugin (MCME-Architect) depends on TheGaffer's protection API in a way that constrains any refactor.

02 — What It Does

The protection model

A default-deny map lock. Every protected action funnels through one method — ProtectionUtil.getBuildProtection() — which permits a build action only when one of these holds:

Bypass permissionthegaffer.ignoreprotection (default OP)
Unprotected worldThe world is listed in unprotectedworlds
External allowAnother plugin's allow-handler returns true
Active in a jobWorker, inside the job's radius, job not paused

A job is therefore a temporary, bounded, revocable grant of build access on an otherwise read-only map. Enforcement also covers hanging entities, specific interactions, all crafting, and an automatic survival↔creative switch at the job boundary. This single method is both the correctness keystone and the performance keystone — most high-priority findings touch it.

03 — Read These First

Headline findings

● P1 · Critical Root cause confirmed

Job persistence was removed for security in 2020 — and never replaced

The storage layer is entirely commented out (JobDatabase.java:32-112). Git history pins it to commit 242c5b1 ("MCMEProject api and security issue", 2020-02-07), which removed the abandoned codehaus Jackson 1.x library — and since that library was the persistence engine, disabled load/save with it. No replacement was ever built, so jobs live only in memory and are lost on every restart, and have been for 3+ years.

Storage did not move to MCME-Connect (verified — that's the network plugin, zero job references). Action: reimplement persistence safely (Bukkit YamlConfiguration, or modern com.fasterxml.jackson with a fixed target type) — don't uncomment the old code.

◆ Cross-repo constraint

MCME-Architect depends on TheGaffer's static protection API

The builder toolset MCME-Architect calls TheGaffer reflectively, by method name, via its TheGafferUtil bridge — hasBuildPermission(Player, Location) and getBuildProtectionMessage(Player, Location) — at ~13 sites. There is no compile-time link, and if the lookup fails Architect fails open (allows building).

Implication: those two static methods are a load-bearing public API. Renaming or changing them during the rework silently disables Architect's protection rather than erroring. Keep the signatures stable, or update both repos in lockstep.

04 — The Audit

Findings by severity

Critical · Stability & data safety
C1Threading

Async cleanup task calls the main-thread-only Bukkit API

TheGaffer.java:110 · CleanupUtil.java:70, 99

The cleanup runs on runTaskTimerAsynchronously but performs scoreboard / inventory / teleport / event work — undefined behaviour that passes testing then corrupts state under load.

Fix Make the cleanup task synchronous (runTaskTimerAsynchronously → runTaskTimer) — this removes async rather than adding it; nothing here is expensive or I/O-bound.

C2Concurrency

Shared job collections mutated from two threads

JobDatabase.java:29-30 (TreeMaps) · CleanupUtil.java:58

The async task iterates the job maps while the main thread mutates them → intermittent ConcurrentModificationException / corruption.

Fix Resolved for free by making the cleanup task synchronous (C1).

C3Lifecycle

No onDisable() — no clean shutdown

TheGaffer.java (absent)

/reload stacks duplicate tasks & double-registers listeners; in-memory state (abandoner timers, /job prep inventories) is lost.

Fix Add onDisable() — cancel tasks, persist state, restore prepped inventories.

C4Memory

Unbounded memory leak in the logger

Util.java:11, 32

Every log call appends to a static list that is never read or cleared — and debug() appends even when debug is off. Grows without bound.

Fix Delete the list (or make it a bounded ring buffer).

P1Persistence

Job persistence disabled since 2020 — see headline

JobDatabase.java:32-112 · commit 242c5b1

Jackson removed for security; persistence never replaced. Jobs are lost on restart.

Fix Reimplement persistence safely (YAML or modern Jackson). Implementation lands in Roadmap Step 6.

High · Performance (hot paths)
H1Hot path

Protection check allocates & rescans on every block action

ProtectionUtil.java:62, 65

Builds two HashMaps over all jobs per edit — including an areas map that is never read. O(jobs × workers) + 2 allocations on the hottest method in the plugin.

Fix A Map<UUID, Job> player-index + per-world job lists; delete the dead areas map today.

H2Hot path

playerMove runs the expensive scan twice

PlayerListener.java:54, 63

getJobWorking + getBuildProtection per block-boundary move, per player — on the highest-frequency event in Minecraft.

Fix One lookup; early-return when no jobs are active; act only on real gamemode transitions.

H3Events

Per-job listeners + dead event dispatch

Job.java:40 · JobDatabase.java:119 · JobEventListener.java:163-186

Every Job is its own listener (join/quit fan out to N handlers), and five custom events fire on every action with empty handlers.

Fix One listener over the registry; gate event dispatch on registered listeners; drop the empty handlers.

H5Identity

Identity by player name, not UUID

Job.java:52-56, 151 · 28× getOfflinePlayer(String)

The deprecated name overload can block on a Mojang lookup; names change, silently orphaning members, bans and invites.

Fix Store UUIDs, resolve names for display. Own milestone + one-time converter.

High · Broken / surprising behaviour
P2New feature

Project feature can NPE / ClassCastException

JobCreationConversation.java:382, 393

A field-initializer casts the McMeProject plugin lookup directly, then calls it — null if absent, CCE if it doesn't implement the interface.

Fix Null-check and resolve through a safe accessor.

B2Commands

/job admin path is fragile

JobAdminCommands.java:51, 76, 99

Omitting the name throws AIOOBE (args[3]); addhelper is missing from its map; a bad job name → null → NPE. Reflection dispatch throughout.

Fix Validate arity & job before dispatch; replace reflection with explicit handlers.

B4Scope

CraftingListener blocks all crafting, ignoring the world exception

CraftingListener.java:25

Cancels crafting for any non-bypass player everywhere — even in unprotectedworlds (e.g. plotworld), inconsistent with the rest of the model. Unchecked cast too.

Fix Honour the same world/permission exceptions as getBuildProtection.

B6Logic

Batch invite / ban / kick short-circuit on the first player

Job.java:336-355

inviteworker a,b skips b entirely if a is already invited.

Fix Accumulate per-player results instead of returning inside the loop.

B7Permissions

Permissions are never registered

PermissionsUtil.java · plugin.yml (no permissions block)

thegaffer.join's intended default: true has no effect unless a perms plugin grants it.

Fix Declare the permissions in plugin.yml.

B1·B3TeamSpeak

TeamSpeak bugs moot after TS removal

JobCreationConversation.java:436 · JobAdminConversation.java:449-454

TS channel discarded (setTs/setTS key mismatch); setTeamSpeakchannel prompt is a no-op. TeamSpeak is retired at MCME.

Fix Delete the dead TeamSpeak code (Roadmap Step 2) rather than repairing.

Medium · UX & latent bugs
M1Data loss

removeWorker wipes the player's entire inventory

Job.java:324 · (and abandoner auto-cleanup) · leaveJob does not

Real item loss; behaviour is inconsistent between leave / kick / ban / abandon.

Fix Only clear job-kit items, and make the behaviour consistent & opt-in.

M2Input

/job archive <non-number> throws

JobCommand.java:305

Integer.valueOf on raw input → NumberFormatException + console error.

Fix Parse with a fallback to page 1.

M3Noise

Console spam & loud audio; debug on by default

Job.java:543-571 · JobEventListener.java:99 · config.yml:3, 12, 43

Un-gated Logger.getGlobal on every team change; server-wide wither-death sound on job start; debug: true default; duplicate TS key.

Fix Remove stray logging; gate/soften the sound; default debug off; de-dupe config.

M4Correctness

Owner-timeout drops the old owner; timezone & message bugs

CleanupUtil.java:99 · JobEventListener.java:131 · GafferResponses.java:57

selectNewOwner never re-adds the offline owner as helper; getLondonTime() mislabels UTC as London (wrong in BST); a message reads literally %name (missing %).

Fix Demote the owner directly; use ZoneId.of("Europe/London"); fix the token.

M5UX

Case-sensitive job names

JobCommand / JobDatabase

Players must match exact case for join / info / stop — the README even warns about it.

Fix Case-insensitive keys (TreeMap with CASE_INSENSITIVE_ORDER).

Low · Cleanup & modernization
L1Dead code

Dead code & vestigial config

Start() · unused Methods maps · empty handlers · servlet config · dead getFile()/dirty

Unused methods, duplicated registries, and config that nothing reads.

Fix Remove; much of it disappears with the TeamSpeak cull.

L2Versioning

Cross-version fragility in item (de)serialization

JobItem.java:76, 112

Material.valueOf aborts a whole kit/job load on a renamed material; Enchantment.getByName can return null → NPE.

Fix Tolerant lookups with logged skips on unknown keys.

L3Minor bug

Book author set to its title; kit edge cases

JobItem.java:91 · JobKit.replaceInventory

Saved books get the wrong author; kit restore can NPE / silently drop overflow items.

Fix Use the real author; null-guard and handle full inventories.

L4Style

Naming conventions

Private · For / Min / Max · fileSeperator (typo)

Capitalised locals/fields and a misspelled identifier hurt readability.

Fix Rename to Java conventions during the touch-ups.

L5Build

Non-reproducible build & no tests

pom.xml:71 (hardcoded VentureChat systemPath) · no src/test

Build depends on an absolute path on one machine; zero automated tests.

Fix Install the jar to the local repo / use a real dependency; add a test scaffold + CI.

L6Modular

Static-singleton state throughout

TheGaffer.java · JobDatabase.java

Global mutable statics make testing hard and reloads fragile (compounds C2/C3).

Fix Optional longer-term: pass a plugin/service instance instead of statics.

05 — Credit Where Due

Already fixed since 2019

The 36 commits between the old fork and v2.8 did land some real fixes — worth noting so the rework doesn't re-litigate them:

Scoreboard overflow — team names truncated to 14 chars (Job.java:109-113)
Threading (partial) — JobEndEvent now dispatched on the main thread (JobDatabase.java:137)
Material rename — DANDELION_YELLOW → DANDELION
QoL — /job leave added; /job join auto-joins a sole job

Also preserved & good: the GafferResponse enum pattern, the external-handler extensibility, and the Conversation-API job creation flow.

Don't break the Architect contract

Steps 6–7 touch the most code. Either keep them stable, or land a matching update to MCME-Architect/util/TheGafferUtil.java in the same release.
